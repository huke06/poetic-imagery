# 诗象志 · 古诗词意象智能体

> 一字藏万象，一诗见千年。

以古典诗词**意象**为核心切口，集「意象知识图谱、诗画联动展示、演变脉络可视化、智能问答创作」于一体的轻量化古诗词文化智能体。

当前版本收录意象（「柳」「雁」为增量导入演示示例，可一键删除）：

| 意象 | 情感标签 | 收录诗文 | 覆盖朝代 | 导入方式 |
|------|----------|----------|----------|----------|
| **月** | 思乡 · 怀人 · 孤寂 · 时空永恒 | 33 首 | 先秦 → 清 | 种子脚本 |
| **夕阳** | 怀古 · 落寞 · 时光流逝 · 离愁 | 26 首 | 先秦 → 清 | 种子脚本 |

## 一、快速启动

### 1. 后端（FastAPI + SQLite）

```bash
cd backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # 如遇镜像 403，加 -i https://mirrors.aliyun.com/pypi/simple/
.venv/Scripts/python scripts/rebuild_all.py                # 一键重建演示数据库（月/夕阳/柳/雁，含对仗/古画/关联）
.venv/Scripts/python run.py                                # 启动于 http://127.0.0.1:8000
```

> 数据库文件不入库（见 .gitignore），`rebuild_all.py` = 种子数据 + 全部示例增量包，一条命令完整复现演示数据；只想初始化两个核心意象时也可只跑 `scripts/seed.py`。

- 接口文档（自动生成）：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/health

### 2. 前端（Vue 3 + Vite）

```bash
cd frontend
npm install        # 国内建议 npm install --registry=https://registry.npmmirror.com
npm run dev        # 启动于 http://127.0.0.1:5173（已代理 /api、/static 到 8000）
```

浏览器访问 **http://127.0.0.1:5173** 即可。

### 3. 可选配置（`backend/.env`，参考 `.env.example`）

| 变量 | 说明 |
|------|------|
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 大模型（OpenAI 兼容协议，豆包/通义千问均可）。**不配置时智能助手自动使用本地知识库模板生成，完全离线可用** |
| `UPSTREAM_WRITING_BASE` | 上游诗文库地址（默认 `https://open.cnkgraph.com`），用于平仄/笺注/出处等透传；本地精选库未挂接上游 ID 时自动回退本地计算 |
| `ADMIN_TOKEN` | 管理后台接口令牌（默认 `shixiangzhi-admin`） |

## 四、意象知识库搭建说明（重点）

当前意象的数据**不依赖上游接口**，由文学常识人工精选构建（月/夕阳落在 `backend/scripts/seed_data.py`，柳为 `add_concept.py` 增量导入示例），结构如下：

### 1. 意象本体（`CONCEPTS`）
每个意象包含：本义、诗词引申义、四枚情感标签、起源/鼎盛朝代、**按朝代书写的演变史**（诗经萌芽→汉魏奠基→唐鼎盛→宋深化→元明清转型），以及别称表（月=婵娟/玉盘/冰轮…，夕阳=落日/斜阳/残阳…，用于问答关键词匹配）。

### 2. 诗文与关联（`POETRIES`）
- 选篇原则：**每个情感标签都有 3 句以上代表作支撑**，每朝代都有节点作品，形成完整演变链。两意象共 56 首，其中《忆秦娥》《苏幕遮》《临江仙》3 篇同时关联「月」与「夕阳」，构成意象共现网络。
- 每条「意象-诗文」关联人工标注四元组：`(含象诗句, 情感标签, 是否经典名句, 权重1-3)`。
  情感标签严格限定在该意象的四枚之内，因此**情感分布环形图、朝代折线图全部由真实关联数据计算得出**，不是写死的展示数据。

### 3. 对仗词组（`COUPLETS`）
从已收录律句中提炼高频对仗（如「明月—清风」「浮云—落日」），含例句与出处，支撑详情页对仗区。

### 4. 古画（`ARTWORKS`）
画名、作者、年代、材质、尺寸、藏馆均为**真实著录信息**（如马麟《夕阳秋色图》藏根津美术馆）；每幅画附「诗画关联阐释」。图像当前由 `svg_art.py` 生成的水墨占位图（离线可靠），接入艺术品库 appkey 后可替换为真实高清图。

### 5. 自动计算（`seed.py`）
朝代统计表 `dynasty_stats` 由关联数据自动汇总；句读切分自动完成。扩充新意象时只需在 `seed_data.py` 追加同构数据并重跑 `seed.py`，前端图表、问答、创诗即自动生效。

### 6. 后续接入真实上游数据的路径
1. 诗文库：用「组合搜索」接口（`/api/writing/find`）按意象词检索 → 清洗后写入 `poetry` 表并回填 `source_writing_id`，平仄/笺注/出处即自动切换为上游透传；
2. 艺术品库：注册 artlib.cn 获取 appkey/secret → 拉取图文库元数据写入 `artwork` 表并替换 `image_url`；
3. 朝代统计重跑 `seed.py` 的统计段即可。

## 五、扩充新意象（重要）

支持**三种方式**，按数据量选择：

### 方式 A：后台「批量导入」上传文件（推荐，最省事）

管理后台（`/admin`）→「批量导入」页：**下载模板 → 填写 → 上传（可多选）→ 校验预览 → 执行导入**。
拖拽上传，先校验后落库，错误逐行指出；重复导入自动幂等（诗文/古画按 名称+作者 去重复用，不产生重复数据）。

> 📁 **模板文件就在项目根目录 `templates/` 下**（`concept_template.json` / `poetries_template.csv` / `concepts_template.csv` / `填写说明.txt`），直接编辑后上传即可；界面上的下载按钮读取的也是这几个文件。

| 模板 | 携带内容 | 说明 |
|------|----------|------|
| **JSON 模板** | 全量：本体+诗文+对仗+古画+关联 | 单意象或 `{"concepts":[...]}` 批量；**也可只写部分段落，作为已有意象的「补充包」**（如只含 couplets+relations 用于后补对仗与关联） |
| **CSV · 意象本体表** | 骨架：名称/分类/别称/情感标签/本义/引申义/演变史 | 一行一个意象；**已存在的意象自动补全空缺字段** |
| **CSV · 诗文关联表** | 诗句：一行一条「诗文-意象」关联 | 全文换行写字面 `\n`；情感标签空格分隔；`concept_category/concept_tags` 只需首行填 |

**推荐组合**：`本体表 + 诗文表` 一次同传建成完整意象；后续再用 JSON「补充包」追加对仗/古画/关联。
（库中的「雁」即按此流程建成：先诗文表建骨架 → 再本体表补全含义 → 再 JSON 补充包加对仗/古画/三条关联，样例见 `backend/scripts/examples/`）

> CSV 需 UTF-8 编码（Excel 导出选「CSV UTF-8」）。校验规则：情感标签必须在该意象标签集内（补充包可省略标签，自动继承库中已有标签）；诗句未含意象词/别称会给提示（间接关联可放行）。

### 方式 B：命令行增量导入（同一套引擎）

```bash
cd backend
.venv/Scripts/python scripts/add_concept.py --check scripts/examples/poetries_sample.csv   # 校验
.venv/Scripts/python scripts/add_concept.py scripts/examples/poetries_sample.csv          # 导入
.venv/Scripts/python scripts/add_concept.py --delete 雁                                   # 删除意象
```
JSON/CSV 均可，样例见 `backend/scripts/examples/`（concept_liu.json / poetries_sample.csv / concepts_sample.csv，模板见 `concept_template.json`）。

### 方式 C：后台各面板逐条录入

「意象管理」「诗文管理」「古画管理」「关联管理」「对仗管理」面板手动增删改，适合零散修补。

---

### 选篇与标注的经验法则
- **每个情感标签 ≥3 句代表作**，饼图才均衡；**每个主要朝代有节点作品**，折线图才连贯
- 优先选兼含多个意象的作品（如《忆秦娥》兼有月/柳/残照），共现关系自动加密关联网络
- `weight`：3=千古名句 2=名篇警句 1=一般关联；`is_classic=1` 的句子会成为意象卡片封面句
- 情感标注与名句权重建议保留人工环节（或 LLM 初标+人复核），这是知识库质量的核心

### 后续接真实上游数据
1. 诗文库（open.cnkgraph.com）：「组合搜索」按意象词批量拉诗 → 整理成 CSV 走方式 A 导入，回填 `source_writing_id` 后平仄/笺注/出处自动切换上游透传；
2. 艺术品库（artlib.cn）：注册获取 appkey/secret → 元数据写入 `artwork` 表并用「古画管理-图片」替换 image_url。

## 六、管理后台（可视化配置）

浏览器访问 **http://127.0.0.1:5173/admin**（页脚有入口），输入管理令牌（默认 `shixiangzhi-admin`）即可使用，共八个面板：

| 面板 | 功能 |
|------|------|
| 数据总览 | 库规模统计、意象清单、大模型状态、朝代统计一键重算 |
| 批量导入 | **JSON/CSV 文件上传批量导入**（模板下载、拖拽上传、校验预览、幂等去重） |
| 系统配置 | **热修改**大模型 Key/地址/型号、上游接口地址、管理令牌（写入 `backend/runtime_config.json`，即时生效，无需重启；留空回落 `.env`） |
| 意象管理 | 新建/编辑/删除意象；主题色支持**分类色族推荐**（见下「配色体系」） |
| 诗文管理 | 检索、录入、编辑诗文及其意象关联标注（含象诗句/情感/名句/权重）、回填上游 writingId |
| 古画管理 | 元数据 CRUD + **图片三接入**：① 外链 URL（artlib 等图库）② 本地上传文件 ③ 一键重生成水墨占位图 |
| 关联管理 | **数据推导的关联建议**（共现作品+共同情感自动计算，一键采纳）+ 人工关联维护 |
| 对仗管理 | 对仗词组增删改查 |

> 关联图的「真实化」：详情页关联网络中，实线为人工标注的学理关系（对仗/情感同源/演变衍生），**虚线为系统依据共现作品实时推导的关联**（附共现篇目），随数据扩充自动加密。

## 七、配色体系（50+ 意象规模）

`backend/app/utils/palette.py` 实现「**分类色相族 + 名称哈希**」确定性配色：

- 每个分类绑定一个传统色族：天象→青蓝族（石青/黛蓝/靛青…），植物→青绿族（竹青/艾绿/松石绿…），动物→赭黄族，器物→沉雅族，地理→山水族，人事→绛红族，每族 10 个传统色号
- 同族内按意象名 MD5 哈希取色：**同族近似、异族有别、完全确定**（同名单次计算恒同），50 个意象也能保持和谐
- 生效路径：后台新建意象未选色时自动分配；`add_concept.py` 的 JSON 中 `theme_color` 留空同理

## 八、常见问题

- **Windows 控制台中文乱码**：属终端 GBK 显示问题，不影响接口与页面数据。
- **端口被占用**：`netstat -ano | findstr :8000` 找到 PID 后 `taskkill //PID <pid> //F`。
- **重置数据库**：删除 `backend/shixiangzhi.db` 后重跑 `python scripts/seed.py`。
